# Contributing

Thank you for taking the time to contribute to a Nodal Studio project.

## Before you start

- **Bugs** — search the existing issues first, then open one with the bug report template:
  what you did, what you expected, what happened, and the version you used.
- **Features** — open an issue to discuss the idea before writing code, so we can agree on
  the scope and the approach.
- **Security issues** — never in a public issue. See [SECURITY.md](SECURITY.md).

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep the change focused: one topic per pull request.
3. Follow the conventions of the code around you (formatting, naming, structure). Run the
   project's linters and tests before pushing — the README of each repository explains how.
4. Add or update tests for any behaviour you change, and the documentation if needed.
5. Write clear commit messages that explain *why*, not only *what*.
6. Open the pull request and fill in the template. We review every contribution and will
   get back to you.

By contributing, you agree that your contribution is licensed under the license of the
repository you contribute to, and you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
